# Workspace layer

`src/workspace/` is the live layer: it discovers TypeScript solutions, loads their projects through the TypeScript compiler API (in memory, never writing to disk) and resolves symbol specs.

| Module | Responsibility |
|---|---|
| `discovery.ts` | Walk roots, collect `tsconfig.json` files, decide solutions vs projects |
| `solution.ts` | `SnapshotHost` (LanguageServiceHost), `loadProject`, `loadSolution`, unresolved-import count |
| `manager.ts` | `WorkspaceManager`: `discover`, `register`, `load`, `resolveSolution`, `findSolutionForPath`, `status`, `resolve` |
| `symbolSpec.ts` | Pure symbol-spec parser |
| `declarations.ts` | Declaration kinds, ranking, name index, fully-qualified names |
| `resolver.ts` | Resolve a spec to a `ResolvedSymbol` within a loaded solution |
| `search.ts` | `searchInSolution`, `searchWorkspace`, `formatSearch` (ranking itself is in the `index` layer) |
| `positions.ts` | 1-based position printing |
| `packages.ts` | `packageOf`, `packageModulePath`: the package and module path a file's docId is scoped by |
| `git.ts` | `GitProvider`, `createGit`: merge base, changed files and base texts from git (the only module that starts a process) |
| `review.ts`, `reviewFormat.ts`, `reviewImpact.ts` | `reviewChangesText`: changed files and declarations against a git merge base, on a forked base-side service, with reference/caller/relation counts per declaration |

## Vocabulary

- **Solution**: a `tsconfig.json`. A tsconfig with `references` is a solution whose referenced tsconfigs are its **projects**; a tsconfig without references is a solution with exactly one project, itself. References are followed transitively (a project referencing another project adds it to the solution once); referenced tsconfigs that do not exist are skipped. A solution tsconfig that has references is not itself loaded as a project.
- **Solution name**: the name of the directory containing the tsconfig.
- **Project name**: `name` from `package.json` in the project's directory if present, else the directory name. Only the project's own directory is consulted (no walk up to a monorepo root, which would give every project the same name).
- **Discovery**: walk each configured root to depth 6 (the root is depth 0), skipping folder names in `ignoredFolders` (default `node_modules .git dist build out coverage`), and collect every `tsconfig.json`. A tsconfig referenced by another collected tsconfig is a project, not a solution. Solutions are sorted by path.
- **Loading**: one `ts.LanguageService` per project with a custom `SnapshotHost`. File lists and compiler options come from `ts.parseJsonConfigFileContent(ts.readConfigFile(...).config, ts.sys, dir)`. File contents are read from disk once and kept in an in-memory snapshot map; `SnapshotHost.setFile(path, text | null)` replaces a file in memory without touching disk. All projects of a `WorkspaceManager` share one `ts.DocumentRegistry`.
- **Project references**: `projectReferences` from `parseJsonConfigFileContent` are served through `getProjectReferences()`, and the host implements `useSourceOfProjectReferenceRedirect() { return true; }`, so imports of a referenced project resolve to its source files instead of its (possibly unbuilt) `.d.ts` output.
- **Load metrics**: computed per project in one pass over `program.getSourceFiles()` (default libs skipped) and summed per solution; `LoadedProject`, `LoadedSolution` and `SolutionStatus` carry them.
  - `rootFiles`: files listed by the tsconfig (same as `fileCount` on a solution). Projects whose `files` list only entry points have few roots but a much larger program.
  - `sourceFiles`: non-declaration files of the program outside `node_modules` (roots plus everything they import).
  - `declarationFiles`: `.d.ts` files of the program outside `node_modules`.
  - `unresolved: { relative, package }`: see below. `unresolvedImports` is their sum.
- **Unresolved imports**: missing `node_modules` never fail loading. Every `import`/`export ... from`/`import x = require()` specifier in every `sourceFiles` file (not only root files) that the checker cannot resolve to a module is counted. `unresolved.relative` counts specifiers that are not bare package names: starting with `.` or `/`, or matching a `paths` pattern, or whose first segment exists under `baseUrl`. `unresolved.package` counts the remaining bare specifiers (typically uninstalled third-party packages), so a high `package` count with `relative` 0 means "node_modules missing", while `relative > 0` points to genuinely broken local imports.
- **Position**: `{path}:{line}:{col}`, 1-based line and column (`getLineAndCharacterOfPosition` + 1), path as given by the program, forward slashes.

## Symbol spec grammar

Forms are tried in this order; the first match wins (`parseSymbolSpec` returns `null` when none matches).

1. **Position**: `^(?<path>.+?\.(ts|tsx|mts|cts|js|jsx)):(?<line>\d+)(?::(?<col>\d+))?$`, case-insensitive, line and column > 0. The path is absolute or relative to the solution directory.
   - Without a column, the declaration whose name starts on that line with the best rank wins: class/interface/type alias/enum (0) > function/method/accessor/constructor (1) > property/field/variable (2) > other declarations (3) > parameters and locals (4); ties go to the leftmost. If the line has no declaration, the first identifier on it that refers to a symbol is used.
   - With a column, the identifier at that column is used; if there is none (e.g. the column is one past an identifier) the column before it is tried.
2. **`Name(params)`**: the parameter text is split on top-level commas; each parameter is reduced to its type (`a: string` → `string`, `...rest: T[]` → `T[]`, `b?: number` → `number`) with whitespace removed and lower-cased. `Name` is resolved, then the first overload/signature whose parameter type list matches (by type annotation text or the checker's type string) is preferred; a class name prefers a matching constructor. Without a match the normal best candidate is returned.
3. **Generic** `Foo<T,U>`: type arguments are removed and the name resolves as `Foo` (TypeScript has no arity suffix).
4. **Qualified** `A.B.C`: `A` is resolved like a bare name (candidates tried in rank order); each further part is looked up through namespace/module exports, enum members, instance members (including inherited) and static members of classes, and properties of a value's type. `A` may also be a file-level module: `shapes.Circle` resolves through the exports of `shapes.ts` (tried after declaration candidates). `Type.constructor` and `Type.Type` (when `Type` has no member named `Type`) mean the constructor; a class without an explicit constructor answers with the class declaration and kind `constructor`.
5. **Bare name**: exact-name match over the non-local declarations of every file in the solution's programs (function bodies are not entered). Order: project source first; default libraries and `node_modules` declarations only rank after every project declaration; then types (class, interface, type alias, enum) → functions → variables and namespaces → members (methods, properties, fields, enum members, accessors). Ties: source beats `.d.ts`, then the shortest fully-qualified name, then path order, then position.

**Normalisation**: aliases are resolved to the original declaration before answering — renamed imports (`import { A as B }`), renamed re-exports (`export { A as B }`), `import x = ...`, and identifiers that refer to imported symbols.

## Resolution across solutions

`WorkspaceManager.resolve(spec, { solution? })`: with a solution hint only that loaded solution is searched (matched by full path, then exact name, then name substring); otherwise every loaded solution is searched in load order and the first match is returned. Unresolved specs return `null`; resolution never throws. Internal errors are passed to the optional `onError` callback of `resolveInSolution` or, without one, printed to stderr when `DOMRA_DEBUG` is set. The bare-name index is cached per `ts.SourceFile` (unchanged files are not re-walked after an edit) and merged per program. There is no index fallback yet.

## Result shape

```ts
type ResolvedSymbol = {
  name: string;        // declaration name; "constructor" for constructors
  fqName: string;      // dotted chain of enclosing namespaces/classes/interfaces/enums, e.g. "Geometry.Point.origin"
  kind: SymbolKind;
  solution: string;    // solution name
  project: string;     // name of the project owning the declaring file
  position: { path: string; line: number; col: number };  // 1-based, of the declaration name
  isDeclarationFile: boolean;
  signature: string;   // checker.symbolToString; functions/methods append signatureToString, e.g. "makeCircle(radius: number): Circle"; constructors "new Circle(radius: number): Circle"
};
```

`SymbolKind` is one of `class interface typeAlias enum enumMember function method property field variable parameter namespace module constructor accessor`. Class `PropertyDeclaration` → `field`; `PropertySignature` and object-literal properties → `property`; get/set accessors → `accessor`; type parameters → `parameter`.

## Search

`searchInSolution(solution, pattern, { kind?, limit? })` ranks every named declaration of a loaded solution; `searchWorkspace(manager, pattern, { solution?, kind?, limit?, onError? })` runs it over the hinted solution or every loaded solution (load order), omitting solutions without hits, and never throws. The pure ranker lives in `src/index/ranker.ts` and `src/index/projectKinds.ts`; `src/workspace/search.ts` walks each program's source files once through `fileNameIndex` (default libs, `node_modules`, and alias nodes — import/export specifiers, `import x =` — are skipped; hits are deduped across projects by path and start offset).

**Query parsing**: terms are the pattern split on space, `.` and `:`, trimmed, empties removed. The last term is the name term and is the only ranked part (against the symbol's simple name); earlier terms are container terms, each a case-insensitive substring of the hit's `fqName` or of its path relative to the solution directory. An empty query has no results.

**Match quality** (first that applies, `null` drops the hit): `exact` (equal ignoring case) → `lastHump` (name ends with the pattern, ignoring case, at a hump start) → `prefix` → `camelHump` → `substring`.

**Hump rules**: a hump starts at index 0; after an underscore at any non-underscore character; at an upper-case letter that follows a non-upper-case character or precedes a lower-case letter (every upper-case letter in a *pattern*); at a digit after a non-digit; at a letter after a non-letter. Underscores never start a hump. `HTTPClientFactory_v2` → `[0, 4, 10, 18, 19]`. `matchesHumps` splits the pattern at its hump starts (trailing underscores trimmed) and scans the name's humps in order, greedily, each pattern hump consuming the next name hump that starts with it (ignoring case); humps need not be adjacent. `UOC`/`UpOrCo` match `UpdateOrderCommand`, `uoc` does not, `retry` matches `CreateRetryOptions`. Checks are Unicode-aware.

**Sort** (ascending): `isTest` (non-test first) → match quality → kind rank → name length → `fqName` (ordinal, ignoring case) → path (ordinal, ignoring case) → offset. `limit` (default 30) applies per solution after sorting; `total` is the count before it.

**Kind rank**: 0 class, interface, typeAlias, enum, function, method, constructor; 1 property, accessor; 2 field, enumMember; 3 variable, parameter, namespace, module. The `kind` option is an exact filter on `SymbolKind`.

**Test detection** (`isTestProject(projectName, relativePath)`): a hump equal to `Test`/`Tests` (ignoring case) in a project-name segment split on `.`, `/`, `-`, `@` (`acme.UnitTests`, `@mono/core-tests` yes; `Latest`, `contest` no); or a path segment `test`, `tests`, `__tests__`; or a file name matching `.test.` / `.spec.` with a js/ts extension.

**Output** (`formatSearch`): per group a header `Live {solution} ({total}):`, then one line per hit `  {kind} {fqName}  {path}:{line}:{col}` (LF endings, trailing LF). Without any hit the text is `No symbols match {pattern}. Patterns support camel-case humps (e.g. UOC for UpdateOrderCommand).` with no trailing newline. Paging comes with the server.

## Queries

`definition`, `symbolInfo` and `listMembers` (`src/workspace/queries.ts`) take `(solution, spec, options)` and return `QueryText = { head: string[]; items: string[]; label: string; footer?: string }`. `formatQueryText(text, limit)` prints `head`, the first `limit` items, `  ... {N} more` when items remain, then `footer` (LF after every line except `footer`, which has none; the server appends cursors). Queries never throw: internal errors go to `onError` (or stderr with `DOMRA_DEBUG`) and the result is the not-found text. A declaration-file symbol is answered like any other (no decompilation). Resolution is `findInSolution` (the resolver without `toResolved`) so queries keep the node and checker.

**Header** (`formatHeader`): `Symbol: {signature}  [{kind}]  {fqName}`, `Project: {project} ({solution})` (`({solution}, declaration file)` for `.d.ts`), `Defined: {path}:{line}:{col}`.

`WorkspaceManager` also has `unload(hint): boolean` (drops a loaded solution and disposes its language services; the registration stays), `findRegistered(hint)` (a registered solution, loaded or not) and an `onLoad` callback fired after a solution was newly loaded (the server queues indexing from it). The server replaces the `Tip:` line below with index candidates, see `docs/server.md`.

**Not found** (`formatNotFound(spec, parsed, solutionKnown)`): a name spec or an unparsable spec gives `Symbol not found in any loaded solution: {spec}` and `Tip: use search_symbols to find the exact name, or load_solution if the owning solution is not loaded yet.`; a position spec gives `No symbol at {spec}` and either `The file is not under any loaded solution.` or `Point the column at an identifier, or omit the column to take the first declaration or reference on that line.`

**`definition`**: header, `Declared in source:` (`Declared in declaration file:` when every declaration is in a `.d.ts`), then one `  {path}:{line}:{col}` item per declaration of the symbol (function overloads and merged interfaces/namespaces each count), deduplicated by position and sorted by path then offset. Label `go_to_definition {fqName}`. In the server a declaration under `node_modules` is redirected to the package's source when the index knows it, or gets `Source:` lines (`docs/server.md`, index fallback).

**`symbolInfo`**: `head` lines, each omitted when it does not apply: `Signature`, `Kind`, `Name`, `Modifiers` (`modifiersOf`: accessibility for class members, `static abstract readonly async override declare export default`), `Namespace`, `Module` (first declaration relative to the solution dir), `Containing type`, `Project`, `Declared at` (one per declaration), `Extends` / `Implements` (heritage text), `Type parameters`, then for functions/methods/constructors `Returns` and `Parameter: {type} {name}[?][ = {init}]` per call/construct signature (`Overload {n}:` before each block when there are several), for properties/fields/variables/parameters/accessors `Type` (and `Accessors: get|set|get set`), `Constant` (enum members, `const` literals), `Decorators`, `Docs:` (`  summary: ...` and `  {tag}[ {param}]: {text}`), and for types `Members ({count}):` with up to 60 `  {compactOf}` lines in source order and `  ... use list_members for the full list`. Label `get_symbol_info {fqName}`.

**`listMembers(solution, spec, { filter?, includeInherited?, limit? })`**: the target is a class, interface, enum, namespace/module or an object-type alias; a member spec uses its containing type; anything else answers `{spec} is not a type.` Members are the declared property/method/constructor/accessor declarations and signatures of every declaration (constructor parameter properties are `field`s), enum members, exported namespace declarations or the type literal's members; index signatures and implicit members are excluded. `includeInherited` walks base types breadth first, adds `  [from {declaring type}]`, and keeps only the nearest declaration of a name (per static/instance). `filter` is a case-insensitive substring of the name, applied before counting. `head`: `{kind} {fqName}  {path}:{line}:{col}` and `{N} members` (after filter, before limit); items `  {accessibility} {static }{kind} {compactOf}[  [from X]]`. `limit` is the page size the caller passes to `formatQueryText` (default `DEFAULT_LIMIT` = 200); the query itself returns every member.

**Member order**: public before non-public; then kind rank (field/property 0, accessor 1, constructor 2, method 3, other 4); then distance from the target (own members before inherited ones); then name (ordinal, case-sensitive); then offset. Label `list_members {fqName}`.

**`compactOf`** (no modifiers): `{name}({p: T, q?: U, ...r: V}): R` for functions, methods and call signatures (`constructor(...)` without a return type; `= {initializer}` after a parameter's type), `{name}{?}: {type}` for properties, fields, variables, parameters and accessors, `{name} = {value}` for enum members with a constant value, and `{name}` plus `<T, U>` for classes, interfaces, aliases, enums and namespaces. Types always come from `checker.typeToString(..., NoTruncation)`.

## Outline

`outline(solution, target, { depth = 2, includePrivate = true })` (`src/workspace/outline.ts`) returns a `QueryText` with one line per declaration, so an agent can read only the span it needs. It is a pure syntax walk (function bodies are never entered); the checker is only used for the compact text. It never throws; internal errors go to `onError` (or stderr with `DOMRA_DEBUG`) and the result is the not-found text. The limit is applied by `formatQueryText` (default 300 in the CLI).

**Target**: a string ending in `.ts .tsx .mts .cts .js .jsx` is a file path (absolute or relative to the solution directory, either slash); anything else is a symbol spec resolved with `findInSolution`.

**File outline**: head `Outline: {path}  (Live {solution}, {project names})`, footer `Total: {n} declarations` (before any limit), label `get_outline {path}`. A missing file gives `File not found: {target}. Pass an absolute path, or a path relative to a solution directory.`; a file on disk that no project program contains gives `{path} is not part of {solution}. New files are picked up on save; otherwise check the project globs.`

**Entries** (source order, depth first): top-level classes, interfaces, type aliases, enums, functions (each overload signature and the implementation separately), namespaces/modules and each declarator of a `const`/`let`/`var` statement (span = the whole statement). Imports, exports, `export { ... }` and expression statements are skipped. Nested (+1): members of a class, interface, enum or type-literal alias in source order (fields, constructor followed by its parameter properties as `field`, methods and overloads, get/set accessors as `accessor`, enum members; index signatures skipped) and the declarations of a namespace (recursively).

**Depth**: 1..3, clamped. 1 = top level only, 2 = also members and namespace declarations, 3 = also members of nested types (e.g. classes in namespaces).

**Entry line**: `{indent}{text}  {start}-{end}` (`{start}` when equal); indent = `2 + nesting * 2` spaces; lines run from `getStart` (after leading trivia and JSDoc, decorators included) to `getEnd`. Text: `[{accessibility} ][static ]{kind} {compact}[ : {heritage}][  [Dec] [Dec]]`.

- **Accessibility**: `private`/`protected` as declared on class members (`#x` is `private`); top-level and namespace-level declarations that are not exported are `private`; `public` and exported print nothing. `includePrivate: false` hides private entries and everything under them.
- **Compact**: `compactOf`; a variable's type is printed without enclosing declaration, so `const shape = new Round(2)` reads `shape: Circle` rather than the local import alias.
- **Heritage**: the text after `extends`/`implements` of every heritage clause of a class or interface, joined with `, `.
- **Decorators**: `[Name]`, or `[Name("lit")]` when the first argument is a string literal.

**Type target**: the resolved declaration (or, for a member spec, its containing type) must be a class, interface, enum, namespace/module or type alias; otherwise head = `{spec} resolved to {kind} {fqName}, which is not a type; pass a file path instead.` Head `Outline: {kind} {fqName}  (Live {solution})`; for each file holding a declaration of the symbol (sorted by path) an item `  {path}  ({project})`, then the declaration at nesting 1 and its members per `depth` (1 = the type only). The footer counts entries, not file lines. Label `get_outline {fqName}`; not-found specs use `formatNotFound`.

## References

`findReferencesText(manager, spec, { solution?, allSolutions = true, kind?, scope?, onError? })` (`src/workspace/references.ts`) and `findImplementationsText(manager, spec, { solution?, typesOnly?, onError? })` (`src/workspace/implementations.ts`) return a `GroupedText` (`display.ts`): `head` lines, one `{ header, label, items }` group per solution and a `footer`. `formatGroupedText(text, limit)` prints head, then per group its header, the first `limit` items and `  ... {N} more`, then the footer (no trailing LF); the server pages every group's items with its own cursor. Neither throws; internal errors go to `onError` (or stderr with `DOMRA_DEBUG`) and the result is the not-found text.

**Defining solution and twins**: with a `solution` hint only that solution resolves the spec, else the first loaded solution (load order) where `findInSolution` succeeds. In every other loaded solution (references: only when `allSolutions`; implementations: always) the symbol is looked up again by fully qualified name; it is a **twin** when its declaration file is the same file or, failing that, when its docId (`docIdOf`, see `docs/index.md`) equals the defining declaration's. The docId rule gives a package's source and its published declaration file (`node_modules/{name}/dist/*.d.ts`, or `paths` to a built `dist`) the same id, so a type defined in a shared package's solution has twins in every loaded consumer solution, found on the consumer's `.d.ts` declaration. References are then searched from that `.d.ts` in the consumer solution; `node_modules` hits stay dropped, so only consumer code is listed. For implementations the consumer's heritage map (which skips `node_modules` files) contributes the consumer-side classes. No twin, no group. `findReferencesText` and `findImplementationsText` take an optional `groupSuffix(solutionPath, hits)` that is appended to the header of every group except the defining solution's (the server uses it for the package drift tag, `docs/server.md`).

**find_references**: head = `formatHeader`. Per solution `service.findReferences(file, nameStart)` runs once in every project whose program contains the declaration file; only the group of the declaration itself is kept: `findReferences` returns one group per symbol the token binds to, and a group is the declaration's when its `definition` (file and name offset) is one of the declarations of the symbol at the name node (merged declarations included) or the symbol behind it after unwrapping an import alias. Usages that bind to an interface member, a base member or an override are not references (`find_implementations` shows that relationship), and neither are the declaration names of those members; `Index` groups follow the same rule because the index records every usage under the declaration it binds to. Within the kept groups `isDefinition` entries, default-lib files, `node_modules` files and files outside the program are dropped; duplicates (same file, line, column) are merged. Count **M**. Each hit is `  {path}:{line}:{col}  {project}  {kind}[  in {enclosing}]`, sorted by path (ordinal, ignoring case), line, column. Group header `Live {solution}: {K} references`, or `Live {solution}: {K} of {M} references ({filter})` when a filter is active. Footer `Total: {sum of K} references[ ({filter})]`, plus ` (defining solution only; pass allSolutions=true to include other solutions)` when `allSolutions` is false. The project column is the project whose root files own the file, else the project whose service reported it.

- **Kinds** (syntax only, no checker): the token at the reference; when it is the name of a property access or the right side of a qualified name the whole access is used. `decorator` = the access/call chain ends in a decorator; `invocation` = callee of a call or tagged template; `creation` = operand of `new`; `base` = type in an `extends`/`implements` clause; `import` = inside an import/export specifier, import clause, namespace import or `import x = ...`; otherwise `usage`.
- **Enclosing** (`in ...`): the nearest ancestor that is a function, method, constructor (`Type.constructor`), accessor, property, enum member, variable declaration, named class, interface, enum, type alias or namespace, printed as its fully qualified name. Arrow functions, blocks and parameters are not stops. Without a stop: `<top-level>`, or no suffix inside an import/export declaration.
- **Filters**: `kind` is comma-separated (`usage, invocation, creation, base, decorator, import`; blanks ignored, case-insensitive); the filter text lists kinds in that canonical order (`kind=base,import`) and `scope=production|tests`, joined by `; `. `scope`: `all` (default), `production`, `tests`/`test`; a test hit is one where `isTestProject(project, path relative to the solution)` holds. Unknown values give a single head line `find_references: unknown kind '{x}'. Accepted: ...` / `find_references: unknown scope '{x}'. Accepted: all, production, tests.` and an empty footer. Not found: the `formatNotFound` lines and footer `Total: 0 references`.
- A bare name resolves like every other tool (types outrank functions), so `Tag` can mean a lib type; pass `path:line:col` to pick the exact declaration.

**find_implementations / find_derived_types**: per solution a heritage map is built once per call from every class and interface declaration in every project program (default libs and `node_modules` skipped; heritage types resolved with the checker, aliases unwrapped; declarations deduplicated by file and offset). Interface target: `implements` = classes implementing it directly, through derived interfaces or through a base class, transitively; `inherits` = interfaces extending it, transitively. Class target: `inherits` = classes in its transitive `extends` closure. Member of an interface: `implements` = the same-named member declared in each implementing class; member of a class: `overrides` = the same-named member in each derived class (abstract members behave like class members; `#private` names and constructors are skipped). Lines `  {implements|inherits|overrides}  {kind} {fqName}  {path}:{line}:{col}`, ordered by relation, then fqName, then path. Header `Live {solution}: {N}`; declarations already listed for an earlier solution are skipped, and a twin group with nothing left is omitted. Footer `Total: {sum}`. `typesOnly` (find_derived_types) on a non-class/interface gives the head `{spec} resolved to a {kind}, not a type. Use find_implementations for members.` and `Total: 0`; labels are `find_implementations ...` / `find_derived_types ...`.

## Call graph

`getCallGraphText(manager, spec, { solution?, direction?, includeExternal?, scope?, limit?, groupSuffix? })` (`callGraph.ts`) returns a `GroupedText` with one level of callers and callees of a function-like symbol, live only (no depth, no recursion, no index fallback). The root is resolved with `resolveTargets` as in `find_references` (twins in other loaded solutions included). Roots: function declarations, arrow functions and function expressions behind a variable or property, methods, method signatures, constructors, accessors, and a class (treated as its constructor: callers are its `creation` sites, callees the body of its explicit constructor, none without one). Any other kind (interface, enum, type alias, namespace, plain variable or property) gives only the head `{spec} resolved to {kind} {fqName}. get_call_graph needs a function, method, constructor, accessor or class; use find_references for types and values.` An unknown symbol gives the `find_references` not-found head; an unknown scope gives `get_call_graph: unknown scope 'x'. Accepted: all, production, tests.`; neither has groups or a footer.

- **Head**: `formatHeader(resolved)`. Footer: empty. `direction` is `both` (default), `callers` or `callees`, ignoring case; other values mean `both`.
- **Callers** (`Callers ({kept}[ of {all}, scope={scope}], live, loaded solutions only):`, label `get_call_graph callers of {name}`): the reference hits of the root and its twins of kind `invocation` or `creation`, one row `  {caller}  {path}:{line}:{col}  {solution}` per site, where `caller` is the hit's enclosing declaration (`<top-level>` kept). Callers keep dispatch: `gather` also returns the hits of the other groups that are related to the root up (a base or interface member it overrides or implements) or down (an override or implementation of it) by declared heritage, never up-then-down, so a call on a sibling override is not a caller. Such a row ends with `  via {Member}` (the member the call binds to). When any `via` caller is listed the header reads `Callers ({n}: {d} direct, {k} via base or interface members, live, loaded solutions only):`. `direct: true` (CLI `--direct`) keeps the callers that bind to the root itself. Defining solution first, then twins in loaded order; inside a solution by path, line, column. `scope` is judged on the call site's project. `groupSuffix` is appended to the header once per twin solution that contributed rows (`hits` = its rows).
- **Callees** (`Callees ({kept}[ of {all}, scope={scope}], source only; includeExternal=true adds node_modules and lib calls):`, with `includeExternal` just `Callees ({kept}[ of {all}, scope={scope}]):`; label `get_call_graph callees of {name}`): a syntax walk of the body of every declaration of the root (overloads included, nested functions and callbacks included) for calls, `new` expressions and tagged templates. The callee is `getResolvedSignature(node).declaration`, else the symbol of the callee expression (aliases followed, `super` via its type); anonymous signatures (call/construct signatures) also fall back to that symbol, so `String(x)` is `String` and an implicit constructor is its class. Deduplicated by docId keeping the first site in source order. Row `  {fqName}  {path}:{line}:{col}  called at {path}:{line}:{col}`; for external callees (default lib, or under `node_modules`; skipped unless `includeExternal`) the declaration column is `(lib)` or `(declaration file)`. Rows are ordered by call-site position. `scope` is judged on the callee declaration's project; external counts as production. A root in a declaration file prints the single row `  (declaration file; no source body to walk)`.

## Diagnostics

`diagnosticsText(manager, target, { solution?, minSeverity?, onError? })` (`src/workspace/diagnostics.ts`) returns a `QueryText` with the compiler diagnostics of the live programs, without a build. It never throws; failures give a single head line.

- **Severity**: `Error` → `error`, `Warning` → `warning`, `Suggestion`/`Message` → `info`. `minSeverity` is `error`, `warning` (default) or `info`/`information` (case-insensitive; anything else means `warning`); diagnostics ranked error 0, warning 1, info 2 are kept up to the minimum.
- **File target** (matches `.ts/.tsx/.mts/.cts/.js/.jsx`): an absolute path, or one relative to the hinted solution's directory, else to the first loaded solution directory where it exists, else to the cwd. The solution is `findSolutionForPath` else the hint; none → `No loaded solution contains {path}`. The owners are all projects whose program contains the file; none → `{path} is not part of {solution}. New files are picked up on save; otherwise check the project globs.` Before analysing, the file is read from disk and, when it differs from the host's snapshot (`SnapshotHost.getText`), `setFile` is called on every owner. Diagnostics are syntactic + semantic (+ suggestion diagnostics for `info`) of each owner.
- **Project target** (anything else): the hinted solution, else the first loaded one (`No solution loaded.`). Projects match by name (ignoring case) or by directory; none → `No project named {target} in {solution}. Projects: {names}`. Diagnostics are the program's options, global, syntactic and semantic diagnostics, minus those in default libraries and `node_modules`.
- **Lines**: `  {path}:{line}:{col}  {severity} TS{code}: {message}` (`  {severity} TS{code}: {message}` without a file), deduplicated on (code, path, start, message) and sorted by severity, path (ordinal, ignoring case), line, column. Head `Diagnostics for {scope}: {E} errors, {W} warnings (compiler only; lint is not run)` where scope is the file path or the matching project names; label `get_diagnostics {scope}`; no footer.
- CLI: `diagnostics <root> <target> [--min-severity s] [--limit n] [--solution s]` prints `formatQueryText(result, limit ?? 200)`; exit 1 when the first head line does not start with `Diagnostics for`, else 0 (even with errors).

## Change review

`reviewChangesText(manager, { solution?, base?, includeTests = true, git, defaultSolution? })` (`review.ts`, lines in `reviewFormat.ts`) is async (it runs git) and returns a `QueryText`: `head` is the `Review:` line, `items` the file, declaration and diagnostic lines (paged by the caller), label `review_changes {solution} vs {base}`, `footer` the `Total:` line. It never throws.

- **Solution**: `solution`, else `defaultSolution`, else the first loaded solution. Unknown: `Unknown solution: {name}. Known: {loaded names}`; registered but not loaded: `review_changes: {name} is not loaded; call load_solution first.`
- **Git** (`git.ts`, `createGit(gitPath)`; `execFile`, 64 MB buffer, 120 s timeout): `probe` (`--version`, cached) fails with `'{gitPath}' could not be started ({message}); install git or set gitPath in the config`; the repository root is the nearest directory upwards holding `.git` (else `{solution path} is not inside a git repository.`); the default base is `origin/HEAD` (its local branch when that exists), else the first existing of `main`, `master`, `develop`, `dev` (else `No default branch found in {root}: ...`). Changes are `git merge-base {base} HEAD`, then `git diff --name-status --no-renames {mergeBase}` (A added, D deleted, else modified) plus `git ls-files --others --exclude-standard` (added). Every error is a single head line `review_changes: {text}` without items or footer.
- **Freshness**: the disk text of every changed source file that a project program contains is pushed into the owning hosts first (`syncOwners`), so saved edits count even without the watcher. Nothing else in the live hosts or services changes; nothing is written to disk or the index.
- **Classification** (files sorted by path, ignoring case): `tsconfig*.json`, `package.json`, `package-lock.json`, `pnpm-lock.yaml`, `yarn.lock` under the solution directory are project files; a `.ts .tsx .mts .cts .js .jsx` file a project program contains (a deleted file: the one its fork contains) is a source file (a deleted file still in the live program counts as modified; a modified file without base text as added); any other file under the solution directory is other; files outside it are only counted.
- **Base side**: per project with a source change, a forked `SnapshotHost` (same parsed tsconfig, `copyFrom` the live host) where every changed source file gets its merge-base text (`git show`), added files are removed and deleted files are put back as roots; a fresh language service with its own document registry runs on it and is disposed afterwards.
- **Declaration diff**: `extractDocument` symbols of the base side and of the live side, compared by docId: only after `+`, only before `-`, `signature` or `accessibility` different `~ signature`, else a different normalized declaration text (tokens joined by one space, so comments and formatting do not count; classes, interfaces, enums and namespaces compare only their header up to `{`, type aliases of a type literal likewise) `~ header` for class, interface, enum, type alias and namespace, `~ body` for the rest. The header delta lists relation rows gained/lost (`+ implements Shape`, `- inherits Base`, target fqName) and decorators gained/lost (`+ @Tag`), joined by `; `, else `(heritage or type parameters)`. A change is surface unless it is `body` or the declaration is `private`.
- **Diagnostics**: syntactic and semantic errors and warnings of the live service on every changed source file that still exists, deduplicated by (code, path, start, message), ordered by severity, path, line, column.

Lines, in this order: project files `{path}  {status}  (project file, not analysed; run reindex force=true if a package version changed)`; other files `{path}  {status}  (not a source file of the solution)`; added or deleted source files with more than 10 declarations `{path}  {status}  ({n} declarations; get_outline lists them)`; the other source files `{path}  {status}[  surface|  body-only]` (label only on modified files with changes) followed by

```
  + {kind}  {fqName}  {accessibility}  {span}
  - {kind}  {fqName}  {accessibility}  was {span}
  ~ signature  {fqName}  {old signature} -> {new signature}  {span}
  ~ header  {fqName}  {accessibility}  {span}  {delta}
  ~ body  {fqName}  {accessibility}  {span}
```

sorted by line, column, docId (`span` = `{line}` or `{line}-{endLine}`, `accessibility` as the index stores it: `export`/`private` at the top level, `public`/`protected`/`private` for members); then, with any diagnostics, `Diagnostics on changed files: {E} errors, {W} warnings (compiler only; lint is not run)` and `  {path}:{line}:{col}  {severity} TS{code}: {message}` lines.

Head: `Review: {solution}  working tree vs {base} (merge-base {first 7 of the sha})  {N} files changed: {S} source, {P} project, {O} other`, plus `; {n} in test projects hidden (includeTests=true shows them)` when `includeTests` is false and hid source files (`isTestProject(project, path relative to the solution)`), plus `; {n} outside the solution ignored`. Footer: `Total: {S} source files, {D} changed declarations ({surface} surface, {rest} body-only or private), {E} errors, {W} warnings`; hidden files still count in it and their diagnostics are still listed.

Limits: renames show as `-` and `+` (`--no-renames`); there is no staged-only mode (the working tree, staged or not, is compared); lint is not run; project files are not analysed; changes are counted, not traced beyond the impact lines below.

**Impact lines** (`reviewImpact.ts`): a non-private declaration line may be followed by one line indented 6 spaces with counts only (never locations); `SplitCount` is `{n}`, or `{n} ({p} production, {t} tests)` when a hit is a test hit. Entries are joined by `, `; `Live {solution} {SplitCount}{drift}` or `Index {solution} {SplitCount}{drift}`.

- `- removed` (any kind): `references: Live {reviewed} {SplitCount} before removal (usages left show as errors below)`, then other solutions with the suffix ` remaining`. The reviewed count is taken on the base side: `gather(target, services)` runs `findReferences` on the fork services (when a non-private removal is listed, every project of the solution gets a fork, not only the changed ones). Twins of a removed symbol are the other loaded solutions where the name resolves to the same docId.
- `~ signature`: `references: Live {reviewed} {SplitCount}` on the working side, plus twins (`resolveTargets` with twins) as `Live {other} ...` and, with `ReviewOptions.index`, `Index {name} ...` for every indexed solution that is not loaded (ordered by name; counts from `countReferencesBySolution`, the test split from the `tests` scope), each with the package drift tag (`[package 1.0.0, source is 1.1.0]`). A constructor counts the creations of its class (`base` hits such as `extends Circle` do not count).
- `~ body` of a method, function, constructor or accessor in a non-test file: `callers: {SplitCount}` (invocations and creations in the reviewed solution and its loaded twins, as `get_call_graph`, `via` callers included; the parenthesis lists `{d} direct, {k} via base or interface members` when k > 0 and `{p} production, {t} tests` when t > 0, joined by `; `). Other kinds, test files and `~ header` have no line.
- `+ added`: interface member `implementations: Live {reviewed} {n}`; abstract class member `overrides: Live {reviewed} {n}` (0 is printed); added interface `implementations:` and `derived types:`, added class `derived types:`, each only when above 0; twins add `, Live {other} {n}`. Counts come from `relationCounter` in `implementations.ts`.
- No impact line for private declarations, for files printed as a summary, for hidden test files, or when the target cannot be resolved.

Limits: callers and relation counts are live and cover loaded solutions only (the index is consulted for reference counts only); references count the usages that bind to the declaration itself (`Live refs 0 before removal` for an override nothing calls directly), while callers keep dispatch through base and interface members and on overrides, counted apart (`callers: 3 (1 direct, 2 via base or interface members)`); the counts of a removed declaration include the references inside the changed files themselves. The index reaches the review through `ReviewOptions.index` (`reviewIndexFor(store)` in `src/server/reviewIndex.ts`), because the server layer imports the workspace layer.

## Indexing

`src/workspace/extractor.ts` (`extractDocument`, `docIdOf`) turns a loaded source file into index rows, and `src/workspace/indexer.ts` (`indexSolution`, `indexDocuments`, `removeDocument`, `isFresh`, `isStale`) keeps the SQLite index current. `classifyReference` and `enclosingOf`/`enclosingStopOf` are exported from `references.ts` so live and index references agree. See [index.md](index.md); the CLI commands `index`, `index-search`, `index-status` and `drift` are described there. `indexSolution` also records the package versions each project consumes from `node_modules` (`package_ref`).

## Developer CLI

`node scripts/domra-cli.ts <command> <root> [args] [options]` discovers solutions under `<root>`, loads `--solution <hint>` (path, exact name or substring; unknown → `domra-cli: no solution matches '<hint>'`, exit 1) or all of them, and prints the text the MCP tools will return. The logic lives in `runCli(argv, { stdout, stderr })` (`src/cli/cli.ts`), which returns the exit code.

- `status <root>`: one line per solution `{name}  {state}  projects={a,b}  rootFiles={n}  sourceFiles={n}  unresolved={relative}/{package}  loadMs={n}` (`-` for null), then `Total: {n} solution(s)`.
- `search <root> <pattern> [--kind <SymbolKind>] [--limit <n>] [--solution <hint>]`: `formatSearch` output.
- `resolve <root> <spec> [--solution <hint>]`: the three `formatHeader` lines; no match prints the `formatNotFound` lines with exit 1.
- `definition <root> <spec>`, `info <root> <spec>`, `members <root> <spec> [--filter <text>] [--inherited]` (all with `--solution <hint>` and `--limit <n>`, default 200): `formatQueryText` of the query result; exit 1 when the first line starts with `Symbol not found` or `No symbol at` or ends with `is not a type.`. Without `--solution` every loaded solution is tried in load order and the first that resolves the spec answers.
- `outline <root> <target> [--depth <1..3>] [--no-private] [--limit <n>] [--solution <hint>]`: `formatQueryText(outline(...), limit ?? 300)`; exit 1 when the first head line starts with `File not found`, `Symbol not found` or `No symbol at`, or contains `is not a type` / `is not part of`. `--depth` is clamped to 1..3, a non-integer exits 2. Without `--solution` an absolute file target uses `findSolutionForPath`, a relative one or a spec is tried against the loaded solutions in load order.
- `references <root> <spec> [--kind <k,...>] [--scope <s>] [--defining-only] [--limit <n>] [--solution <hint>]`, `implementations <root> <spec>` and `derived <root> <spec>` (both with `--limit`, `--solution`): `formatGroupedText(result, limit ?? 200)`; exit 1 when the first head line starts with `Symbol not found`, `No symbol at` or `find_references:` or contains `not a type`. `--kind` is validated as a symbol kind only for `search`.
- `callgraph <root> <spec> [--direction both|callers|callees] [--include-external] [--direct] [--scope <s>] [--limit <n>] [--solution <hint>]`: `formatGroupedText(getCallGraphText(...), limit ?? 100)`; exit 1 when the first head line is a not-found text, starts with `get_call_graph:` or contains `get_call_graph needs`.
- `review <root> [--base <ref>] [--git <path>] [--no-tests] [--limit <n>] [--solution <hint>] [--db <path>]`: `formatQueryText(reviewChangesText(...), limit ?? 200)` (see Change review; git is `--git`, else `DOMRA_GIT_PATH`, else `git`; an existing index file adds the `Index` entries of the impact lines, a missing one is not created); exit 1 when the head starts with `review_changes:` or `Unknown solution`. `review` is asynchronous: `runCliAsync` resolves to its exit code, while `runCli` returns 0 at once and sets `process.exitCode` when the review is done.
- `help` (or no command): usage on stdout, exit 2. Unknown command/option, missing argument, bad `--limit` (positive integer) or `--kind` → message on stderr, exit 2.
- `--verbose` prints diagnostics such as `loaded 3 solution(s) in 812 ms` to stderr.

## Measuring

`node scripts/measure-load.ts <root>` discovers the solutions under `<root>`, loads them all and prints, per solution, its name, projects, `rootFiles`, `sourceFiles`, `loadMs`, `unresolvedRelative` and `unresolvedPackage`, followed by a total line with the same columns.
